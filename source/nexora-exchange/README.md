# Custorium Exchange v2 — تداول حقيقي + محفظة Web3 ذاتية الحفظ

> **اختباري فقط (devnet محلي، بلا تكلفة).** التوكنات لا قيمة لها، وليست نصيحة مالية.
> وثيقة المرحلة: [PHASE-20-NEXORA-EXCHANGE-V2-WEB3.md](../../docs/PHASE-20-NEXORA-EXCHANGE-V2-WEB3.md)

## 1. الفكرة
منصة تداول بأسلوب البورصات المركزية (CEX) مع **محفظة Web3 ذاتية الحفظ داخل المنصة** (مثل Binance Web3 Wallet):
- **المفتاح خاصيتك:** يولَّد ويُخزَّن في متصفحك فقط (localStorage) — السيرفر لا يرى المفاتيح إطلاقًا.
- **التداول حقيقي:** توكنات Custorium الفعلية (nUSD/nXAU/nBTC/nEUR) على شبكة محلية (EVM 902024) مع أوراكل فعلي.
- **تحريك الأصول حقيقي:** الإيداع تحويل ERC20 توقّعه أنت من محفظتك إلى خزنة المنصة، والسحب تحويل حقيقي من الخزنة إلى محفظتك — لكل خطوة `txHash` تتحقق منه على السلسلة.

## 2. المعمارية
| الطبقة | التنفيذ |
|---|---|
| المطابقة | خارج السلسلة — `source/exchange/src/matching-engine.mjs` (نفس محرك بورصة Binance-style) |
| أرصدة حساب التداول | دفتر محاسبي في السيرفر **مدعوم 1:1** برصيد الخزنة على السلسلة (`/api/backing`) |
| الخزنة (custody) | عنوان بمفتاح يولَّد محليًا ويُخزَّن في ملف الحالة — يُموَّل بغاز CSTO تلقائيًا |
| الإيداع | المستخدم يوقّع `transfer` → الخزنة؛ مراقب `eth_getLogs` يقيّد الدفتر خلال ~3-6 ثوان (idempotent) |
| السحب | الخزنة ترسل ERC20 حقيقي بعد تحقق توقيع الجلسة عبر `ecrecover(0x01)` على السلسلة نفسها |
| Convert | مبادلة فورية داخل الحساب **ضد مخزون المنصة الفعلي** (دفتر مخزون الخزنة "K") برسوم 0.1% |
| مخزون التحويل | يُشتق من السلسلة عند كل إقلاع (`K = رصيد الخزنة − الالتزامات`) + تعبئة تلقائية بسكّ حقيقي + إصلاح عجز تاريخي محروس (سقف 1000/توكن) |
| المحفظة | ethers v5.7.2 مُرفق محليًا (`public/vendor/` — بلا CDN وقت التشغيل)؛ توقيع في المتصفح عبر `/api/rpc` |
| المصادقة | challenge/nonce → توقيع في المتصفح → تحقق على السلسلة → جلسة Bearer (30 دقيقة، تُحفظ في المتصفح وتتجدد صامتة عند 401) |
| الرسوم | تاكر 0.1% لكل طرف — تُقيَّد كإيراد في دفتر مخزون المنصة K (تظهر في `/api/backing`) |
| الرسم الشمسي | Canvas خالص — شموع 60 ثانية تُبنى من الصفقات الحقيقية فقط (`/api/candles`، حتى 300 شمعة) |
| keeper | يضع أوامر صانع السوق (mark ± tick) باستمرار لتوفير سيولة لكتاب الأوامر |
| faucet | سكّ حقيقي مباشرة إلى محفظتك + 2 CSTO غازًا (فترة تهدئة 12 ساعة/عنوان) |

## 3. التشغيل
```bash
# 1) تهيئة الشبكة + التوكنات + الأوراكل (idempotent)
node source/nexora-exchange/chain/bootstrap.mjs

# 2) تشغيل المنصة (منفذ 4173)
node source/nexora-exchange/server.mjs
# ثم افتح http://127.0.0.1:4173
```
- حالة الشبكة: `/tmp/opencode/demo-chain-state.json` (عناوين التوكنات/الأوراكل/الحسابات).
- حالة المنصة: `/tmp/opencode/nexora-exchange-state.json` (مفتاح الخزنة، الدفتر، الودائع/السحوبات، المخزون K) — **لا تُرفع للمستودع أبدًا**.
- إعادة تشغيل آمنة: `/tmp/opencode/restart-exchange.sh`.

## 4. رحلة المستخدم (3 دقائق)
1. **Web3 Wallet** → Create wallet (المفتاح يبقى في متصفحك؛ استخدم Reveal key للنسخ الاحتياطي).
2. **Faucet** → سكّ حقيقي إلى عنوانك (4 معاملات + غاز).
3. **Enable trading (sign)** → توقيع جلسة (ecrecover على السلسلة).
4. **Deposit** → توقيع تحويلك إلى الخزنة → يظهر في حساب التداول تلقائيًا.
5. **Trade** → Buy/Sell ضد سيولة MM؛ التسوية فورية في الدفتر (CEX-style).
6. **Account → Withdraw** → تحويل حقيقي من الخزنة إلى محفظتك (`txHash` ظاهر).
7. في أي لحظة: **Account → Proof of Backing** يعرض الخزنة على السلسلة مقابل الالتزامات + المخزون.

## 5. API
| Endpoint | الوصف |
|---|---|
| `GET /api/health` | حالة المنصة + الشبكة + الخزنة + إحصاءات التوكنات المدرجة (`listed`) |
| `GET /api/config` · `/api/markets?q=&limit=` | أسواق ديناميكية: `{total, markets}` — بحث بالرمز/الاسم، ترتيب تنازلي بالسعر، حد للعرض |
| `GET /api/orderbook?instrument=XAUUSD` · `/api/trades` | الكتاب والصفقات |
| `GET /api/candles?instrument=XAUUSD&interval=60` | شموع يابانية مجمّعة من الصفقات الحقيقية فقط (فاصل 5-3600 ث، حتى 300 شمعة) |
| `GET /api/account?address=0x…` | أرصدة/مراكز/سجل عنوان |
| `GET /api/backing` | دليل الدعم 1:1 لكل توكن (خزنة الذاكرة المُسوّاة مقابل الالتزامات + مخزون) |
| `POST /api/auth/challenge` · `/api/auth/verify` | جلسة بالتوقيع |
| `POST /api/faucet` | سكّ اختباري (تهدئة 12 ساعة) |
| `POST /api/orders` · `/api/orders/cancel` | تداول (يتطلب Bearer token) — `type: limit` أو `market` (marketable-limit IOC: ما لم ينفَّذ فورًا يُلغى) |
| `POST /api/withdraw` · `/api/convert` | سحب حقيقي (فواصل لكل توكن) / مبادلة (التوكنات الأساسية فقط) (Bearer token) |
| `POST /api/prices` | تجاوز سعر إداري لجلسة الخزينة w05 — `{prices:[{instrument,price}]}` (سلطة التسعير للمستخدم) |
| `POST /api/rpc` | proxy بقائمة طرق بيضاء لتوقيع المتصفح (يمنع `eth_sendTransaction` وغيرها) |

## 6. الحدود الحالية
- محلي/اختباري فقط: بلا KYC، تدقيق، أو بيانات سوق مدفوعة (الأسعار من MockOracle + التسعير الداخلي).
- mnemonic/seed phrase غير مدعوم بعد (مفتاح خاص فقط).
- denom الشبكة الداخلي وإعادة تسمية المجلدات تُدار في جلسة إعادة التسمية الموازية للمستخدم.
- إذا أُعيد توليد الشبكة بgenesis جديد: امسح `nexora-exchange-state.json` قبل التشغيل (حارس الإصلاح يمنع السكّ الضخم تلقائيًا برسالة واضحة).

## 7. التكيّف مع شبكة Custorium (genesis csto + خطة التوزيع)
- **حساب الإدارة/النشر:** خطة توزيع Custorium تعيّن الخزينة **w05** (غير مجمّدة، ممولة بالغاز الأصلي) كناشر/مسؤول معتمد — السيرفر و`redeploy-contracts.mjs` يتبعانها: `CUSTORIUM_ADMIN_PK` env > `/tmp/opencode/custorium-admin-pk` > تصدير w05 من `nexora-plan/keys` > dev0 احتياطًا للشبكات الذاتية.
- **غاز الشبكة:** الشبكة تفرض حداً أدنى لسعر الغاز 0.0001 CSTO (1e14 wei) — السيرفر يستخدم 1.1× ذلك، وحد الغاز صراحة 600k (`CHAIN_GAS_LIMIT`) لتجاوز تقديرات العقدة المقيدة، والواجهة توقّع بـ 1.1e14 بدل 2 gwei.
- **غاز الفوسيت 200 CSTO:** فحص الكلفة القصوى (gasLimit × gasPrice ≈ 66 CSTO) قبل الإرسال يفرض ذلك؛ الرسوم الفعلية ~0.006 CSTO لكل عملية فقط.
- **إقلاع ذاتي كامل:** تمويل غاز الخزنة (1000 CSTO) + تمويل غاز MM (1000 CSTO) + نقل مخزون MM للخزنة + سكّ مخزون التحويل K — كلها معاملات حقيقية موثقة في سجل الإقلاع.

## 8. توكنات الأسهم المدرجة (1000+ سهم/سند حقيقي)
جلسة المستخدم نشرت 539 توكن أسهم عالمي حقيقي من الخزينة w05 (ثم وسّعتها إلى 1000+ شاملة سندات وعملات: USTBILL، EUGOV، INR…)، والمستكشف Custorium Scan يعرضها مع أسعار `exchange_rate`. المنصة تدمجها **ديناميكيًا**:

- **الاكتشاف:** `GET {EXPLORER}/api/v2/addresses/{STOCK_DEPLOYER}/token-balances` يعيد القائمة كاملة (واجهة `/tokens` مقطوعة عند 50 بلا ترقيم). مزامنة عند الإقلاع + كل 10 دقائق، مع سقوط رشيق إلى ذاكرة السجل عند تعطل المستكشف. الأسعار تُستورد نصًا من `exchange_rate` لكل توكن (`GET /api/v2/tokens/{address}`) على دفعات خلفية (100/30 ث) — سلطة التسعير للمستخدم، و`POST /api/prices` لتجاوزها إداريًا.
- **الأسواق:** كل توكن مدرج = سوق `{SYMBOL}/nUSD` في `marketByInstrument` + `tokenBySymbol` — `/api/markets` يعيد `{total, markets}` مع `?q=` بحث و`?limit=` (الواجهة تعرض 120 مع عدّاد ومربع بحث). الفواصل العشرية لكل توكن (الأسهم 0، السندات 2/6) عبر `decOf/toUnits/rawUnits` — الأسهم بالحصص الكاملة فقط (شراء/سحب كسري يُرفض).
- **مراقب الإيداع:** نداء `eth_getLogs` **واحد** لكل دفعة (custody كمتلقٍ Transfer، بلا فلتر عنوان) بدل نداء لكل توكن — `log.address` يُحلّ للرمز عبر `addressToSymbol`، مع كسر تكرار `processedTxs`، وتخطي خروج الخزنة وسكّات `0x0`.
- **دعم الخزنة (backing):** أرصدة الخزنة تُحفظ في ذاكرة `state.custodyChain` (تراقب +/−) ويُتحقق منها من السلسلة على شريحة دائمة (`reconcileCustodyBatch` 80/30 ث) — `/api/backing` يغطي 1000+ توكن دون 1000 نداء لكل طلب.
- **سيولة مزوّد الأسهم:** المزوّد = **w05** (مالك 100% من كل سهم). ترحيل تدريجي بسعر تنازلي (6 توكنات/10 ث، ~15-20 دقيقة للقائمة كاملة) يوجه كل رصيد w05 إلى الخزنة — المراقب يقيد كتاب w05 تلقائيًا. كمية الأوامر مشتقة من هدف اسمي 2500 nUSD (حصة صحيحة للفواصل=0). تمويل جهة الشراء: تحويل **دفتري داخلي** 30000 nUSD من مخزون K إلى كتاب w05 (nUSD تبقى في الخزنة فيزيائيًا — الثابت C=L+K سليم بالضبط، و`syncInventory` يعيد الاشتقاق عند كل إقلاع). جهة البيع فورية للسهم المُرحّل؛ جهة الشراء تبدأ بالأرخص وتتسع عضويًا مع إيرادات بيع w05 (السهم الأغلى من رصيد التمويل يبقى بيعيًا فقط حتى تتراكم السيولة). Convert يبقى للتوكنات الأساسية الأربعة فقط.
- **الواجهة:** بحث الأسواق + العدّاد، قوائم إيداع/سحب/إرسال ديناميكية (الأساسية أولًا)، فواصل لكل توكن في التوقيع، سجل الإيداع يعرض `amount` البشري، وخطوة الكمية 1 للأسهم (حصص كاملة).
