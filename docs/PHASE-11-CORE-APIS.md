# Phase 11 — واجهات API الأساسية (Core APIs)

> **الحالة:** قيد التنفيذ (بدون تكلفة، محلي/اختباري)  
> **المرجع:** [ZERO-COST-DEV-PLAN.md](./ZERO-COST-DEV-PLAN.md)

## 1. الهدف
توفير طبقة واجهات برمجية موحدة (محلية) للوصول إلى وظائف النظام الأساسية:
- الأصول والأسعار (محاكاة)
- الأوامر والصفقات
- المحافظ والمراكز والتقييم
- الاستعلامات المبنية من الفهرس/الحالة

## 2. النطاق
### داخل النطاق
- وحدة API محلية في `source/api/src/core-api.mjs` تجمع خدمات المراحل السابقة (pricing, exchange, portfolio, indexer).
- عمليات أساسية (commands/queries) عبر واجهة برمجية داخلية واضحة وقابلة للاختبار.
- توحيد التحقق من المدخلات والأخطاء.
- اختبارات Node لتدفقات end-to-end محلية على مستوى الخدمة.

### خارج النطاق (هذه المرحلة)
- نشر HTTP عام أو مصادقة إنتاجية
- توليد OpenAPI كامل/تكامل UI (يمكن إضافته لاحقًا)
- تحسينات أداء إنتاجية

## 3. التصميم المقترح
واجهة `createCoreApi()` تُرجع كائنًا بخدمات/طرق مثل:
- `assets`: تسجيل/تحديث/استعلام الأصول (read model)
- `pricing`: تحديث/قراءة أسعار محاكاة وتقييم
- `trading`: وضع/إلغاء أوامر، استعلام دفتر/صفقات
- `portfolio`: إيداع/سحب، تطبيق fills، لقطات، تقييم بالمؤشرات
- `indexer`: تطبيق أحداث واستعلام حالة/لقطات

## 4. خطة التنفيذ
1. إنشاء `source/api/src/core-api.mjs` و`source/api/test/core-api.test.mjs`.
2. تنفيذ تكامل حتمي بين الوحدات الحالية.
3. تشغيل `node --test source/api/test/*.mjs`.
4. تحديث التقدم والوثائق ودفع التغييرات.

## 5. معيار القبول
- تدفقات أساسية (أصل، سعر، أمر، صفقة، محفظة، تقييم) تعمل محليًا عبر واجهة موحدة.
- الاختبارات تمر محليًا.
