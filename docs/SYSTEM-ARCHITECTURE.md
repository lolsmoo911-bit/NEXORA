# NEXORA — معمارية النظام (Phase 2 Baseline)

> **الحالة:** Baseline معماري محلي/وثائقي (بدون تكلفة)  
> **المرجع:** [ZERO-COST-DEV-PLAN.md](./ZERO-COST-DEV-PLAN.md) — المرحلة 2

## 1. الهدف المعماري
تصميم نظام معياري (modular) يربط بين:
- **طبقة البلوكشين (EVM)** للهوية/السجلات/العقود التمثيلية.
- **طبقة السيرفرات (محلية)** للتسعير المحاكى، المطابقة، المحافظ، الفهرسة، وواجهات API.

مع فصل واضح للمسؤوليات، وقابلية التحقق محليًا، ودعم التطور التدريجي نحو الرؤية.

## 2. المبادئ
- **Local-first / Zero-cost:** التنفيذ الافتراضي محلي بدون اعتماد على خدمات مدفوعة.
- **Determinism حيث يلزم:** التسعير/المحاكاة يجب أن يكون قابلًا لإعادة الإنتاج لنفس المدخلات.
- **Separation of concerns:** العقود لا تحل محل محرك التداول أو التسعير المعقد؛ والسيرفر لا يستبدل سجل السلسلة.
- **Auditability:** أحداث وسجلات قابلة للتتبع (on-chain events + server logs/indexed state).
- **Safety by design:** صلاحيات واضحة، حالات دورة حياة، وفحوصات مدخلات.

## 3. الطبقات والمسؤوليات

### 3.1 Blockchain Layer (EVM / Local Devnet)
**المسؤوليات:**
- هوية الأصول وربطها (`AID`, `AssetRegistry`, عقود مرتبطة).
- عقود التمثيل (test-only primitives) وإدارة حالات الأصول/الرموز.
- إصدار أحداث (events) للفهرسة: تسجيل أصل، تحديث حالة، عمليات إصدار/نقل (ضمن النطاق المدعوم).
- (لاحقًا ضمن الخطة المحلية) واجهات Oracle محاكاة on-chain.

**المكوّنات الحالية/المرجعية:**
- `source/aid/` (مواصفة وعقود AID)
- `source/contracts/` (عقود اختبارية)
- `source/chain/`, `source/ci/` (تهيئة وتشغيل/تحقق محلي)

### 3.2 Pricing & Market Simulation Layer (Local)
**المسؤوليات:**
- تسعير/تقييم حتمي للأدوات المدعومة (سندات، منحنيات، spreads، FX، سيناريوهات).
- توليد سيناريوهات ومقاييس مخاطر أساسية (محليًا).
- استهلاك أسعار محاكاة (mock feeds) وإنتاج مخرجات تقييم موحدة.

**المكوّنات الحالية/المرجعية:**
- `source/market/` (نواة market/pricing canonical)

### 3.3 Trading & Portfolio Services Layer (Local Server)
**المسؤوليات (مخطط):**
- **Matching Engine (Simulated):** استقبال الأوامر، المطابقة، الإلغاء، وتوليد أحداث تداول.
- **Portfolio/Positions:** تتبع الأرصدة، المراكز، PnL، والتعرض.
- **Settlement (Simulated):** حالات التسوية الافتراضية والضمان المحاكى.
- **Risk/Controls:** حدود أساسية، circuit breakers محاكاة، وفحوصات سلامة.

**الموقع المستهدف (تطوري):** خدمات ضمن `artifacts/` أو حزم/وحدات خادم محلية جديدة (حسب التنفيذ المرحلي).

### 3.4 Indexing & Data Access Layer (Local)
**المسؤوليات (مخطط):**
- قراءة أحداث السلسلة/الخدمات ومعالجتها بشكل idempotent.
- بناء نماذج قراءة (read models) للاستعلام السريع (أصول، أوامر، صفقات، محافظ).
- دعم إعادة البناء (replay/rebuild) من الأحداث/السجلات.

### 3.5 API Layer (Local)
**المسؤوليات (مخطط):**
- واجهات موحدة للأصول، الأسعار المحاكاة، الأوامر، الصفقات، المحافظ، والتقييم.
- فصل أوامر الكتابة (commands) عن الاستعلامات (queries).
- تحقق مدخلات، أخطاء موحدة، وتوثيق واجهات.

**المكوّنات الحالية/المرجعية:**
- `artifacts/api-server/` (قاعدة حالية قابلة للتوسع ضمن القيود)

## 4. واجهات وتعاقدات بين الطبقات (Contracts Between Layers)

### 4.1 Chain ↔ Indexer
- **المدخلات إلى Indexer:** أحداث العقود (logs/events)، بيانات كتل/معاملات (محليًا).
- **المخرجات:** جداول/نماذج قراءة للأصول، الحالات، والتحويلات ذات الصلة.
- **متطلبات:** idempotency، ترتيب أحداث، قابلية إعادة المعالجة.

### 4.2 Market/Pricing ↔ Trading/Portfolio
- **المدخلات إلى Pricing:** أسعار محاكاة/بيانات منحنيات/معلمات أدوات.
- **المخرجات:** تقييم، مقاييس مخاطر/سيناريوهات.
- **الاستهلاك:** مطابقة (عند الحاجة)، تقييم محافظ، تقارير.

### 4.3 Mock Oracle/Feed ↔ Pricing & Contracts
- **المدخلات:** مولد بيانات محلي/ملفات/سيناريوهات.
- **المخرجات:** تحديثات سعر مع حالة جودة (fresh/stale/outlier/unavailable).
- **الاستهلاك:** عقود Oracle محاكاة (لاحقًا) وخدمات التسعير/المحرك.

### 4.4 Trading/Portfolio ↔ API
- **Commands:** إنشاء/إلغاء أمر، إجراءات إدارية (محكومة بالصلاحيات).
- **Queries:** الأصول، دفتر الأوامر، الصفقات، المحافظ، التقييمات.
- **النتائج:** استجابات موحدة + أحداث/سجلات تدقيق.

## 5. التدفقات الأساسية (Core Flows)

### 5.1 تدفق إصدار أصل تمثيلي (محاكاة)
1. تعريف الأصل (metadata + type + lifecycle draft).
2. تسجيل/التحقق من الهوية (AID/AssetRegistry) على devnet محلي.
3. نشر/ربط عقد تمثيل (test-only) بالأصل.
4. تفعيل الأصل للسوق المحاكى (active) بعد فحوصات التحقق.

### 5.2 تدفق تحديث سعر (Mock Oracle)
1. مولد التغذية ينتج سعرًا/مؤشرًا محاكى.
2. تمرير التحديث إلى Oracle محاكى (off-chain/on-chain حسب المرحلة).
3. تحديث حالة الجودة (fresh/stale/outlier).
4. استهلاك السعر في التسعير/المحرك/المحافظ.

### 5.3 تدفق تداول محاكى (Order → Match → Settlement Simulation)
1. المستخدم/العميل يرسل أمرًا عبر API (محلي).
2. خدمة الأوامر تتحقق من الصلاحيات والمدخلات والقيود الأساسية.
3. Matching engine يطابق الأوامر وفق القواعد.
4. توليد أحداث صفقة/تحديث دفتر أوامر.
5. Settlement محاكى يحدّث الأرصدة/المراكز والحالة (settled/failed/cancelled).
6. Indexer يحدّث نماذج القراءة للتقارير والاستعلامات.

### 5.4 تدفق تقييم المحفظة
1. قراءة المراكز والأرصدة من خدمة المحافظ/نماذج القراءة.
2. جلب أسعار/مدخلات تسعير محاكاة.
3. استدعاء Market Core لإنتاج التقييم والمقاييس.
4. إرجاع النتائج عبر API وتسجيل اللقطات عند الحاجة.

## 6. نموذج البيانات (مبدئي)

### كيانات أساسية (مقترحة)
- **Asset:** `assetId/AID`, type, symbol/name, metadata, lifecycle state
- **Instrument/Token Representation:** contract address/type, supply rules, linkage to asset
- **Price Point:** asset/instrument, value, timestamp, source/mock-provider, quality
- **Order:** side, type, quantity, price, status, owner/account
- **Trade/Fill:** matched orders, qty, price, fees (simulated), timestamp
- **Position:** account, instrument, quantity, avg cost/basis
- **Portfolio Snapshot:** balances, positions, valuation, risk metrics

## 7. حدود الثقة والأمان (ضمن النطاق المحلي)
- **On-chain:** عقود test-only، بدون تدقيق، مع اختبارات محلية.
- **Server:** صلاحيات محلية، تحقق مدخلات، سجلات تدقيق، وفصل أوامر/استعلامات.
- **Data feeds:** محاكاة فقط (لا تمثل أسعار سوق حقيقية موثوقة للإنتاج).
- **Keys/Secrets:** مفاتيح تطوير/اختبار فقط، بدون أسرار إنتاج.

## 8. خارطة التنفيذ المرحلية (ارتباطًا بالخطة)
- **Phases 3–5:** توحيد نموذج الأصول، عقود التمثيل، ونماذج التسوية/الضمان المحاكاة.
- **Phases 6–9:** Mock oracle، تكامل التسعير، matching engine، والمحافظ.
- **Phases 10–12:** الفهرسة، APIs، والصلاحيات.
- **Phases 13–18:** سير عمل الإصدار، دورة حياة السوق، الرصد، الأمان، E2E، والتوثيق التجريبي.
