# NEXORA — نموذج الأصول ومواءمة AID (Phase 3 Baseline)

> **الحالة:** Baseline مواصفة/تصميم (محلي، بدون تكلفة)  
> **المرجع:** [ZERO-COST-DEV-PLAN.md](./ZERO-COST-DEV-PLAN.md) — المرحلة 3  
> **يعتمد على:** [VISION-AND-SCOPE.md](./VISION-AND-SCOPE.md), [SYSTEM-ARCHITECTURE.md](./SYSTEM-ARCHITECTURE.md)

## 1. الهدف
توحيد نموذج تمثيل الأصول عبر:
- **طبقة الهوية والسجل على السلسلة** (`AID`, `AssetRegistry`)
- **طبقة السيرفر/التسعير/التداول المحاكى**

بحيث يكون لكل أصل تعريف متسق، حالات دورة حياة واضحة، وبيانات وصفية قابلة للتحقق والتتبع.

## 2. المبادئ
- **هوية حتمية:** استخدام AID كمرجع هوية أساسي للأصل (حيث ينطبق).
- **فصل الهوية عن التمثيل القابل للتداول:** هوية الأصل (identity) قد تختلف عن عقد/رمز التمثيل (token/instrument contract).
- **بيانات وصفية قابلة للتدقيق:** الحقول الأساسية يجب أن تكون موثقة ومُصدَرة (provenance/source/context) عند توفرها.
- **محاكاة صريحة:** أي ربط بأصل حقيقي في هذه المرحلة هو **تمثيلي/محاكى** ما لم يوجد إطار قانوني ووصاية وإثباتات خارجية.

## 3. تصنيف الأصول المستهدف (Asset Taxonomy)

| `assetClass` | الوصف | أمثلة | ملاحظات تمثيل |
|---|---|---|---|
| `fiat` | عملات ورقية/FX | USD, EUR, JPY | غالبًا تمثيل fungible أو أزواج تسعير |
| `metal` | معادن | XAU, XAG | تمثيل fungible/وحدات معيارية، يحتاج احتياطي/وصاية لاحقًا |
| `energy` | أصول طاقة | Oil, Gas | تمثيل أداة/عقد مرجعي محاكى |
| `equity` | أسهم | Stock indices / single-name (simulated) | تمثيل محاكى، قيود قانونية لاحقًا |
| `bond` | سندات | Govt/Corp bonds | متوافق مع market core (pricing/schedules) |
| `fund` | صناديق | Hedge/Investment funds | وحدات NAV تمثيلية (محاكاة) |
| `crypto` | أصول رقمية أصلية/مرجعية | BTC, ETH (reference) | استخدام سيناريوهات/تسعير محاكى عند الحاجة |
| `custom` | فئات تجريبية/داخلية | Test instruments | للتطوير المحلي والاختبارات |

> يمكن توسيع التصنيف لاحقًا مع الحفاظ على التوافق الخلفي عبر versioning.

## 4. نموذج بيانات الأصل (Canonical Asset Model)

### 4.1 الحقول الأساسية (Core)
| الحقل | النوع | إلزامي | الوصف |
|---|---|---|---|
| `aid` | string/bytes32 (حسب الطبقة) | نعم (عند التسجيل) | معرف الأصل الحتمي |
| `assetClass` | enum/string | نعم | تصنيف الأصل (انظر Taxonomy) |
| `symbol` | string | نعم | رمز مختصر (مثل XAU, EURUSD, BOND01) |
| `name` | string | نعم | اسم الأصل |
| `decimals` | uint8/int | حسب النوع | دقة العرض/الوحدات (للفئات القابلة للتجزئة) |
| `lifecycleState` | enum | نعم | حالة دورة الحياة |
| `metadataURI` | string | اختياري | رابط/مرجع metadata (محلي/وصفي) |
| `metadataHash` | bytes32/hash | اختياري | بصمة محتوى metadata للتحقق |
| `provenance` | object | موصى به | مصدر التعريف/البيانات والسياق |

### 4.2 حقول وصفية مقترحة (Extended Metadata)
| الحقل | النوع | أمثلة/استخدام |
|---|---|---|
| `country` | string | بلد المُصدر/السوق (للأسهم/السندات) |
| `issuer` | string | جهة الإصدار (سند/صندوق) |
| `underlying` | string/object | الأصل المرجعي (للمشتقات/الصناديق/الأزواج) |
| `currency` | string | عملة التسعير/التسوية |
| `venue` | string | سوق/سياق مرجعي (محاكاة) |
| `maturityDate` | date/string | للسندات/الأدوات ذات الاستحقاق |
| `couponRate` | number/string | للسندات |
| `dayCountConvention` | string | متوافق مع `source/market` عند الحاجة |
| `oracleProfile` | string/object | ملف تغذية السعر المحاكاة/الجودة |
| `tags` | string[] | تصنيف إضافي/بحث |

## 5. دورة حياة الأصل (Lifecycle States)

| الحالة | الوصف | انتقالات مسموحة (مبدئية) |
|---|---|---|
| `draft` | تعريف مبدئي غير مفعل | `active`, `retired` |
| `active` | متاح للتسعير/التداول المحاكى (حسب القواعد) | `halted`, `suspended`, `retired` |
| `halted` | إيقاف مؤقت (تشغيلي/مخاطر) | `active`, `suspended`, `retired` |
| `suspended` | تعليق إداري/تحقق | `active`, `retired` |
| `retired` | متوقف نهائيًا عن الاستخدام التشغيلي | — |

**قواعد عامة:**
- الانتقالات يجب أن تكون صريحة ومسجلة (حدث/سجل تدقيق).
- `retired` حالة نهائية (لا رجوع) في النموذج الأساسي.

## 6. المواءمة مع AID وAssetRegistry

### 6.1 دور AID
- `AID` هو **معرف الأصل الأساسي** المرجعي عبر السلسلة والخدمات.
- يُستخدم لربط:
  - سجلات الأصل (off-chain/local indexed records)
  - عقود التمثيل/التداول المحاكى (عند الربط)
  - التغذية السعرية والتقييمات والتقارير

### 6.2 دور AssetRegistry (on-chain)
- سجل تحقق/ربط للأصول (حسب تصميم العقود الحالي في `source/contracts`).
- مسؤول عن فرض قواعد التسجيل والتحقق والهوية (ضمن ما هو منفذ).
- يجب أن يظل متوافقًا مع تصنيف الأصول ودورة الحياة على مستوى البيانات/الأحداث (أو عبر طبقة مواءمة في السيرفر أثناء التطوير التدريجي).

### 6.3 خريطة المواءمة (مبدئية)

| مفهوم النظام | السلسلة (On-chain) | السيرفر/الفهرس (Off-chain local) |
|---|---|---|
| هوية الأصل | AID / registry records | Asset record keyed by AID |
| تصنيف الأصل | حقل/ترميز مدعوم أو metadata hash/ref | `assetClass` صريح في read model |
| حالة دورة الحياة | حالة عقد/سجل (إن وجدت) + أحداث | `lifecycleState` موحد في read model |
| التمثيل القابل للتداول | token/instrument contract | instrument mapping + balances/positions |
| المصدر/السياق | hash/URI/events (جزئي) | provenance object كامل |

## 7. قواعد التسمية والتحقق (Naming & Verification Rules)

- **الرموز (`symbol`)**: فريدة ضمن نطاق السوق/السياق المحدد (أو عالميًا حسب السياسة المعتمدة لاحقًا).
- **الأسماء (`name`)**: وصفية وغير مضللة؛ الأسماء "الرسمية" تتطلب سياسة تحقق أعلى (لاحقًا).
- **التحقق:**
  - التحقق التقني: سلامة الحقول، الاتساق، صحة المراجع/البصمات.
  - التحقق الدلالي (خارجي لاحقًا): صحة ارتباط الأصل بأصل حقيقي/جهة إصدار (خارج نطاق بدون تكلفة).
